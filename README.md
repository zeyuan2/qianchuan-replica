## 微信预算80%提醒

在采集电脑打开 http://127.0.0.1:5173/notifications.html，填写本人pushplus用户Token，保存并测试后开启。微信绑定需要在pushplus完成；该通道是发给Token绑定用户的公众号通知，不是公开文章或普通微信群。计划名称、ID、预算、基础消耗、状态会经pushplus处理。接口code=200仅代表平台受理，微信是否收到以手机和平台记录为准。

每轮完整采集后异步检查当日`stat_cost_for_roi2_primary`（基础整体消耗）/ 当前计划预算 >= 80%，不是整体消耗，也不是综合成本。仅使用10分钟内的当日完整数据；当天达线的暂停计划也包含。只提醒，不修改预算、ROI或启停，不启用低投产规则。

同日、同计划、同预算去重；调高或调低预算后达到80%可再次提醒。每轮最多合并15条，其余在后续轮次继续。平台明确拒绝每5分钟最多重试一次，合计不超过3次；超时或结果不明、进程中断不自动重发。状态及Token保存在被Git忽略的`.runtime/budget-alerts/`，不暴露给内网网页。发送失败不影响采集，关闭浏览器中的设置页不影响后台检查。

协议参考：https://www.pushplus.plus/doc/guide/api.html 。默认关闭，未配置Token时不会发送任何数据。

## 新计划识别规则

第一次完整采集只建立基准，旧快照未收录的计划不会被误报为新计划。之后比较计划ID，不能只比较总数；即使新建一条、删除一条导致总数不变，也能识别新增ID。

创建时间在上轮采集之后的新增ID标记“新计划”；以前创建、现在首次进入范围的ID标记“首次发现”。页面高亮最近24小时发现的计划，支持“只看新增”。已见ID保存在磁盘，重启、暂停后重新出现不会重复标记。

这是周期查询：在两轮之间创建后又删除、且从未出现在任何一次响应中的计划不会被观察到。没有为测试而在真实账户新建计划。

## 操作登录

计划名称下方现在直接提供“一键起量”和“素材追投”按钮，后者使用平台返回的可追投视频清单，最多选择20个视频。所有真实提交都需要操作登录与变更确认。

计划列表顶部“批量一键起量”可独立查询统计日期区间，并按计划名称/ID、当前状态、基础消耗、实际综合营销ROI、净成交订单数、当前日预算的上下限筛选。指标来自该区间真实响应；缺失值不作为0参加筛选。更换日期重新查询会清空勾选；其他筛选变化保留已选并提示筛选外的勾选，可一键移除。

每批最多20条计划，统一填写每条额外起量预算及0.5–24小时的时长。确认页逐项列出计划和额外预算总额，5分钟内有效。后台串行创建，遇到失败或不确定结果即停止后续提交；“停止后续提交”不撤销已创建任务。批次状态持久化于.runtime/batch-boost，网页关闭仍执行已确认批次，刷新后可“查看最近批次”；服务重启不自动重试中断批次。外网操作日志会关联批次ID和登录邮箱。

本次测试仅进行了筛选、素材读取和任务核对预览，没有真实创建一键起量或素材追投任务。

在采集电脑的连接设置页设置独立操作密码（6–128个字符），然后在内网页面右上角点击“操作登录”。会话保持30天，每次使用续期；可主动退出。重置密码会使所有现有会话失效。密码以scrypt加盐哈希保存，会话令牌仅以哈希保存于.runtime/operators.json，浏览器使用HttpOnly、SameSite=Strict Cookie。

每行“操作”入口包含预算、ROI、启停、删除、日志和三类调控工具。提交前先拉取当前计划，展示变更；确认90秒有效并绑定登录会话。删除还需要输入计划ID。提交结果不明确时不自动重试，先检查千川原页和操作日志。

本轮验证未改变真实计划预算、ROI或投放状态，也未真实删除或创建调控任务。写操作的最终权限、风控和表单限制由千川响应决定；恢复入口不代表已实测所有真实写请求。

内网防火墙规则仍需Windows管理员确认；检查.runtime/lan-firewall-result.json，当前未记录成功放行。部署没有关闭防火墙或配置公网映射。
