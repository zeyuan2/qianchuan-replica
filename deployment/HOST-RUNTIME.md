# 主机执行器说明

当前交接状态（2026-10-12）：生产计划自动化已按用户要求停止。以下内容说明代码能力，不构成恢复投放授权；缺少新的明确启用指令时保持关闭。

代码接入 `serve.mjs`；独立Windows服务或额外Node调度器均未创建，同一个工作台进程只运行一套自动化。配置默认为关闭，主机最终配置保存在 `.runtime/automation/config.json`，账户必须与服务器一致，计划必须属于提交的报名申请。配置、事实日志、账本、通知状态和只读探测结果都不得提交Git。

## 启动与停止

脱敏配置格式见 `deployment/automation-config.example.json`，示例账户和计划不能直接启用。主机确认接入后将最终配置的 `enabled` 设为true，再通过原有启动方式启动工作台。`GET /api/automation/status`仅在私有回环服务可读，不通过内网/公网网关公开。

```powershell
node scripts/automation-control.mjs status
node scripts/automation-control.mjs stop
```

停止命令只写入 `.runtime/automation/STOP`，调度器每轮及每次真实提交前检查。正在途中的写入不会被假装撤销；需核对回读和账本。恢复必须由拥有者核对未解决写入后移除STOP并重新启动服务。维护时仍使用 `.runtime/watchdog.pause`。维护标志存在时重启会挂起调度，移除标志后自动恢复；STOP标志存在时不会启动调度。

## 调度语义

00:00、05:00、17:00按北京时间入队，串行处理，不并发修改计划。由于需要逐条实时核对与回读，允许入队后最多5分钟处理窗口；超过窗口的未执行项跳过并上报。进程在时间点之后启动不会补发，即使还在这5分钟窗口内。等待采集/人工操作的时段任务可以在窗口内继续排队，已结算项不会重复执行。

进程启动时最多等待60秒供扩展重新连接；等待期间不读写账户、不发送瞬时离线告警，超过60秒仍离线则正常上报并跳过。

日常规则随完整采集更新评估，另有5分钟兜底评估；读取计划、操作日志及起量状态均通过原有账户约束和浏览器连接。捕获、人工提交、批量提交和自动提交共享活动锁，人工鉴权和确认流程保持原样。自动提交只能由已启用的限定报名配置及规则判断产生。人工请求遇到后台采集或自动检查时，最多等待20秒并优先于后续后台任务取得锁；已开始的查询/提交不被中断。断开的请求与超时请求会从队列移除，不会在用户离开后执行。等待结束重新核验操作登录与写入连接，原有确认过期和计划变更校验继续生效；另一个人工请求或运行中的批量任务仍明确拒绝并发。

## 证据与保守边界

- 从完整分页日志中的新建ROI设置以及后续ROI修改建立时间线，不使用通用modifyTime。
- 规则版本2026-10-08.1：入组核验后立即评估。保留已有审核日期证据，不再要求等待审核通过后的第一个0点；投放/审核状态、最新ROI修改时间与完整历史仍须核实。
- 入组本身不触发预算重置或补发起量。0点的冷启动预算重置、05/17点的一键起量仍按既有时段调度；当日消耗、80%阈值及严格大于1小时的ROI间隔继续适用。
- 日志分页缺失、未知ROI/预算文本、账本与当前设置不一致均阻止新写入。预算历史可能存在600→900、但无法核实是否触发永久停起量时，停止起量并上报。
- ROI/预算组合先落意图，再逐步提交及回读；两项全部回读确认才记组合成功。ROI修改时间以平台操作日志为准。部分成功、超时、重启中断均阻止新操作；只做回读，不重放提交。尚未发出的步骤不会因为重启自动补做。
- 首条自然符合条件的真实动作完成回读前，保持首条验证门控。首条结果不明时不放开其他计划写入。若所有计划都在等待，没有真实动作可验收，则运行状态应明确为 `pilot_waiting_first_eligible_action`。

## 比较窗口及缺数处理

配置 `windowMode: "full-hour"`。真实探测已确认：2秒查询也会包含整小时消耗，秒级金额窗口不可用。经用户确认，使用修改前后各24个完整小时，剔除跨界小时。后窗全部结束后才评价；验证账户/计划、日期、24个不重不缺小时和每项金额，ROI按金额汇总相除。真实整日接口已返回24个完整小时；原始探测结果仅留在主机运行目录。

缺数时保持ROI，达到80%仍可仅加预算并遵守10000元上限。完整合格的后窗可建立下一段基准；已证实ROI低于3.1优先走回调判断，不把基准不足当成忽略亏损的理由。回调目标包含恰好在当前观察起点结束的可靠历史记录。

## 状态与延后ROI

投放状态采用列表/详情的数值代码及开关码，不以显示文字授权。已核实0=投放、8=预算预警、7=预算耗尽；5/手动暂停、52/系统暂停及未知代码保守阻止。列表与详情均需属于已核实状态，预算和ROI编辑权限分别校验。预算耗尽可以在平台权限允许时按规则调整预算，但不新建起量任务。未返回独立审核字段时，保留已核实投放代码的审核证据来源，不臆造审核字段。

冷启动允许连续先加预算，每次成功单独记账和累计ROI目标；后续遵守严格大于1小时，逐笔补调。3.1为进入稳定期的边界，队列目标不越过它；达到3.1时相同封顶目标均记为已满足。人工改ROI后撤销旧队列，保留证据。进入稳定期预算至少1000元并保留更高的当前预算。

## 人工核实与单步恢复

网页“自动化记录”复用操作密码登录。先查平台完整日志，只有尚未提交或本地明确未尝试写入的步骤可补做；已成功步骤不会重复。补做和按现状结束都需要再次核对确认，确认绑定操作者、事务、步骤和实时状态，60秒失效，单次使用。计划变化、过期时段、跨日旧意图或ROI间隔不足会阻止补做。

已提交且结果仍不明确时不能重发、不能强行解除阻塞。已核实部分成功时，操作者可以保留当前平台值、结束未提交步骤并解除阻塞。每次核实、预览、提交、解除都留在原事务账本中；处理不明结果不会清空历史。

## 账本与通知

`state.json`为持久状态，`journal/*.json`为每个动作的意图、步骤和回读记录，`status.json`为运行回执，`notifications.json`为按接收人独立去重的通知结果。已受理不等于微信已送达；不明发送结果不自动重发。明确定义的拒绝最多重试3次，每次至少间隔5分钟。相同跳过原因同计划同日合并去重。

首次部署应保存主机备份、通过测试与只读检查后启用。分支中的人工测试不连接真实账户、不发送微信、不代表已在生产调价。

## 更新与回退

更新前停止新操作并等当前写入回读结束，核对 `pendingWrite`、共享锁及浏览器待处理请求。备份生产源码与本机自动化配置，再增量替换通用模块和 `serve.mjs` 接入部分；保留真实账户映射、原有配置、数据和账本。按原服务脚本重启后读取私有状态端点，确认仅一套调度器、名单、连接及通知结果。

需要回退时先执行停止命令，核实在途写入，将最终配置 `enabled` 设为false，再恢复备份源码并重启工作台。保留全部 `.runtime/automation/` 事实和账本；回退程序不会撤销千川已确认的预算、ROI或起量任务。恢复自动化前必须重新核实未知结果，不能清空账本来重新执行。
